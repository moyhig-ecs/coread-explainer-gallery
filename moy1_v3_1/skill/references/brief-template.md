# BRIEF の雛形(図解の発注書)

作り手(subagent)に渡す前に、これを埋めて `<記録の置き場>/<日付>/<置き場>/BRIEF_vN_<題>_<日付>.md` に置く。作り手には「最初に全部読み、書いてあるとおりに」とだけ言い、要点を依頼文に二重に書かない(食い違いのもと)。

```markdown
# BRIEF vN — <題>(<日付>)

- 発注(逐語): <依頼者の言葉をそのまま>
- 作り手 = <札の名>(<model・effort>)。前作 = `<entry_<札>_v(N-1)/>`(あれば最初に全部読む)。
- 置き場 = `<絶対 path>/entry_<札>_vN/`(前の版の folder は書き換えない)。scratch = `<session の scratchpad>/<題>/entry_<札>_vN/`。**他の札の folder は読まない**。
- 機械と道具: bun <版>・python <path>・anywidget / marimo / jupyterlab の版・Chromium の在り処。**install・通信・git はしない。実験の script を import も実行もしない・data の file を読むだけ。**
- 読み手と最終評価: E1 editor / E2 動画の作者 / E4 「この計器だから、この読みが出た」(+ 参考 E3)。

## 0. 一本の筋(章の順)
## 1. data(読むだけ・表: file | 中身 | 説明の RESULT と札の path)
## 2. 絵(横・縦・奥・糸・場面の瞬間・状態の案)
## 3. 言い方と限定(章の全画面に出す札・書かない語・書いてよい形)
## 4. 台帳に足す行(言える / 読み / 言えない)
## 5. 色(既存の意味を保つ・足すなら validator)
## 6. 照合用の値(実行層が data から読んだ値・合わなければ data が正しい)
## 7. 作るもの・進め方・返すもの(打ち切り N 分・≤ 10 行)
```

書き方の注意:
- 照合用の値は、自分で data から読んでから書く(丸めた値を書かない — 手本の v5 で .5 の付いた値を整数に丸めて書いて作り手に直された)。
- 依頼側の誤り(古い値・取り違え)は、気づいたら BRIEF に「訂正」の節を足して作り手に送る。v5 では稿で廃された η の値を BRIEF に写していた。稿の最新の版の該当節を、BRIEF を書く前に読む。
- 小さな直しは BRIEF を作り直さず、依頼文で「v5.N の小さな直し」として範囲(どの状態だけ)・打ち切り・撮り直す撮影の名を指定する。
