# 共読の一巡 — 図から問いが出て、札で答える

## なぜ
図解の価値は、読み手が図を見て問いを出し、それが data で答えられる形になることにある。AI が「自然に読める」ことと、その読みが正しいことは別なので、答える前に札(PREREG)を凍結し、統制(陽性統制を含む)を通った時だけ読む。

## 手順
1. **問いを逐語で記録**(誰がどの状態を見て言ったか)。問いの言葉(位置・行・語)が図の中で一つに決まるかを確かめ、揺れていれば数を読む前に一問で確かめる。
2. **候補(L3)を 2〜3**: 各候補に三つの印 —
   - (a) 計器に依るか(lens に依らない量 = model 自身の出力の順位・token の数え・τ など)
   - (b) 量の在り処: **persist に在る / 新しい forward が要る / 新しい生成が要る**。「persist に無い」と「量が存在しない」を取り違えない(model の出力の順位はどの位置にもあるが、保存したのは書いた token の順位だけ、など)
   - (c) 稿の柵に触れないか(例: 帯の外の層に述語を繋がない)
   順番 = **lens に依らず persist に在る候補 → forward / 生成が要る候補 → lens に依る候補**。柵に触れる候補は外す。
3. **札の PREREG**(下の雛形)と script を一つの commit で凍結。`--fire` は PREREG と script が commit と同じ(dirty でない)ときだけ走る。凍結の前は `--self-test`(合成の列)だけ。
4. **走らせて RESULT**。統制が落ちたら図の data を書かずに止まり、原因を診断して **新しい札** にする(走った後に定義を動かさない)。
5. **図に戻す**: 状態「図から問いが出て、札で答える」= 図を見る → 人間の問い → AI の候補 → 札を凍結して読む → 答えと言えないこと → 次の問い。台帳の「言える」「言えない」にも一行ずつ。

## PREREG の雛形
```markdown
# PREREG(札 <名>): <問い>(<forward の有無>・<身分 = 記述 / 判定>)
- 日付・機械・実行層 / 書き始めの HEAD
- 発注(逐語)
- 身分 / 凍結の実体(本書と script を一つの commit・dirty なら走らない)
## §0. 事前に知っていること(開示)— 既に見た値・定義を確かめるために読んだ物・見ていない物
## §1. 問い
## §2. 宇宙(行・data・集合・帯・位置の定義)
## §3. 統制(一つでも落ちたら止める): 再現(既知の値を完全に一致で)/ 対応(位置と本文)/ 陽性統制(閾つき)
## §4. 量 / 読み方(凍結した言葉)
## §5. 柵
## §6. 主張しないこと
## §7. 出力(path)
```

## 統制の考え方
- **再現**: この script の読み方で、既に凍結した結果の数を完全に一致で再現する(読み方の誤りを捕まえる)。
- **対応**: 位置・token・本文・行の対応が取れている(byte で照らす・負の id は最後だけ など)。
- **陽性統制**: 量の意味が想定どおりなら必ず出る形(例: 生成した token の多くは model の 1 位 ≥ 0.50・次に書く語は計器の上位 ≥ 0.70)。ずれていれば大きく外れる閾にする。
- 閾は値を見る前に決める。見た後に決めた値(上限など)は §0 に開示する。

## 例(札の名は伏せる)
- 問い「どこから He が湧いてくるのか」→ 候補 ① prompt の名前付きの点 ② 帯の外の層 ③ 温度の抽選 → ③ を `obs_model`(書いた token の model 自身の出力での順位・lens に依らない)で札にした → ある組の行は結論の入口のどこかで 1 位でない語・別の組の行は要の語が全行で 1 位 → 次の問い(1 位は何か・温度 0 なら何を書くか)。
- 先の札は統制 C2(位置 ↔ 本文)で停止 → 多 byte の割れ目 → byte で取る新しい札を凍結し直した。
