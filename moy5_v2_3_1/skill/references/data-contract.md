# 材料の契約(data contract)— 詳細と落とし穴

## 読んでよいもの
- 凍結した札の出力(JSON・npz・png)。出力に provenance(commit・dirty・script と PREREG の md5)があること。
- 札の RESULT(数の写しと、主張しないこと)。図の文は RESULT の「主張しないこと」を越えない。
- 論文(稿)の該当節の **最新の版**。古い版の値(例: 廃された η)を写さない。

## 読まないもの
- 実験の script(import しただけで凍結した結果を書き換えるものがある)。
- 他の作り手の folder・判定・memory(独立に作るため)。

## 数の出し方
1. pack の script(Python)が data を読み、図に要る数を一つの pack(JSON / bin)にまとめる。ここで assert(第一経路)。
2. 頁の JS が pack から描くときに、同じ数をもう一度数える(第二経路)。
3. widget の kernel 側(Python)が data から一から数える(第三経路)。
4. `check_claims.py` が CLAIMS の各行の anchor(file・key・期待値)を data から直接照合(第四経路)。欠け 0 を通過の条件に。

## 落とし穴(実際に起きたもの)
- **token と本文の対応**: token ごとに文字へ復号してつなぐと、多 byte の文字(≈ など)が二つの token にまたがる所で U+FFFD に化け、本文より長くなる → 位置と本文がずれる。token を byte に戻してつなぎ、本文の UTF-8 の byte と照らす(byte-level BPE の表で)。
- **潰す順序**: 上限で潰した順位の median は、偶数個のとき「潰してから」と「取ってから潰す」で値が違う(真ん中の二つの一方が上限より下の時)。札の文と実装を揃え、違えば開示する(柵 = 上限より下を読まない、の弱い違反になる)。
- **丸め**: 表示で丸めた値を照合用に書かない。
- **独立でない行**: 同じ seed で prompt だけ違う行は、出力の頭が同じになることがある。数え方(違う場面の数)を図に書く。
- **label と本文の食い違い**: data の label(例: bind)と本文(He/Hi の結論)が食い違う行は、図から外すか、食い違いを開示する。直さない。
- **計器の妥当域**: lens の fit 域の外の位置は provisional。全画面の限定の札に。
- **生成と読みの logit の違い**: 生成(例: MLX)と読み(例: torch)の framework が違うと、僅差の順位は入れ替わりうる。順位で読むときは限定に書く。
